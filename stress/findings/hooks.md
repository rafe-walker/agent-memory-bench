### Leads for the next pass (from code reading, not yet tested)
- shims: commands that git itself runs (`!` aliases, `submodule foreach`, `rebase --exec`, `bisect run`, hooks) get git's exec-path (`/usr/lib/git-core`, which holds a `git` binary) prepended to PATH, so a nested `git push` may bypass the git shim. `sudo` with `secure_path`, `env -i`, `command -p` also skip PATH. A denial prints SEQ and `shim ack --through SEQ` can be run by the agent itself: check whether the denial text invites it.
- shims: `KRONICLE_SHIM_EXEC="$$:1:"` + `exec git push` in the same pid skips the pulse (deliberate-evasion only). The data dir is read at run time from `$KRONICLE_LITE_DATA_DIR`/`$HOME` unless `--data-dir` was baked in, so a changed HOME means exit 3, fail-open, noted once.
- cc-anchor: one CLI timeout (`push_timeout`, 3 s) starts a 60 s back-off. During it the pulse makes no read and runs on the cached `klpend`, and the offline advisory only fires after 20 consecutive down calls. Test whether a change that lands during the back-off lets a deploy through silently.
